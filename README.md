# Квиз-Дуэль для MAX

Проект команды **«Алгоритм успеха»** для хакатона **«Идея фикс»**. Направление - **«Арена развлечений»**, номинация - **«Продвинутая разработка» (Docker)**.

Короткие дуэли помогают повторять школьные темы вместе с участниками классного чата. Учитель управляет предметами и вопросами, проводит экспресс-квизы, смотрит аналитику и задаёт награду лидеру. Прогресс, рейтинг, предметы и настройки разделены по группам.

- **Проект в MAX:** [открыть бота](https://max.ru/se14839521_bot).
- **Репозиторий:** [DOGi23/quiz_duel](https://github.com/DOGi23/quiz_duel).
- **Готовый Docker-образ:** [dist/quiz-duel-linux-amd64.tar.gz](dist/quiz-duel-linux-amd64.tar.gz).
- **Библиотеки и версии:** [requirements.txt](requirements.txt).

Все инструкции по сборке, запуску и настройке сервера находятся в этом README.

## Требования

- Docker Engine с Linux-контейнерами. На Windows - Docker Desktop в режиме Linux-контейнеров.
- Для запуска через Compose - Docker Compose v2 или новее.
- **Единственная обязательная пользовательская переменная - `BOT_TOKEN`.** Токен передаётся при запуске, не при сборке.
- Для mini-app - публичный HTTPS-адрес, указанный в кабинете бота MAX, и групповой чат, куда добавлен бот.
- Для дуэли нужны два аккаунта MAX. Бот должен быть администратором группы; учителем становится её администратор или владелец.

Бот, API и mini-app работают в одном процессе. SQLite встроен в приложение; отдельный сервер базы данных и Node.js для запуска контейнера не нужны. Ориентир для начального размещения - сервер с 2 ГБ RAM.

Mini-app работает внутри MAX с подписанными данными входа. Обычный браузер не предоставляет отдельного игрового входа или деморежима. Не запускайте одновременно несколько получателей обновлений с одним токеном: перед переносом остановите старый экземпляр.

## Получение проекта и готового образа

```bash
git clone https://github.com/DOGi23/quiz_duel.git
cd quiz_duel
sha256sum -c dist/SHA256SUMS
docker load --input dist/quiz-duel-linux-amd64.tar.gz
```

Архив предназначен для **Linux amd64**. На другой архитектуре соберите образ из исходников по следующему разделу. Если репозиторий закрыт, проверяющему нужен доступ. Вместо Git можно скачать **Code → Download ZIP** и распаковать архив.

В PowerShell контрольная сумма проверяется командой `Get-FileHash dist/quiz-duel-linux-amd64.tar.gz -Algorithm SHA256`: сравните её с `dist/SHA256SUMS`. Загрузка образа выполняется той же командой `docker load`.

## Передача токена

В Bash на Linux введите токен скрыто, чтобы он не попал в историю команд:

```bash
read -rsp 'Токен бота MAX: ' BOT_TOKEN
printf '\n'
export BOT_TOKEN
```

В PowerShell 7.1 или новее:

```powershell
$env:BOT_TOKEN = Read-Host 'Токен бота MAX' -MaskInput
```

Используйте последующие команды запуска в том же терминале. В новой сессии перед пересозданием контейнера передайте токен снова. Копировать `.env.example` в `.env` не требуется; этот необязательный пример содержит только `BOT_TOKEN`.

Интерфейс `0.0.0.0`, порт `8080` и путь базы `/data/quiz.db` уже заданы в Docker-образе. ID бота определяется через MAX API, права учителя - по администратору или владельцу группы. Адрес mini-app задаётся в кабинете MAX; передавать его контейнеру не нужно.

## Сборка контейнера из исходников

Команды выполняются из корня репозитория:

```bash
docker build --tag quiz-duel:submission .
```

Dockerfile использует Go 1.27.3 и зависимости из `go.mod` / `go.sum`. UI, шрифты и иконки уже включены в исходники, отдельная npm-сборка для запуска не нужна.

После сборки выберите один из трёх способов запуска ниже. Контрольные суммы и метаданные в `dist/` относятся к приложенному готовому образу; повторная сборка может получить обновлённые пакеты Debian и другой идентификатор.

## Запуск через Docker Compose

Этот вариант подходит для сервера, где HTTPS reverse proxy уже установлен на хосте. После передачи `BOT_TOKEN` загрузите готовый образ или соберите его и выполните:

```bash
docker compose up -d --no-build --pull never
docker compose logs -f --tail=100 bot
```

Для сборки и запуска одной командой:

```bash
docker compose up -d --build
```

Compose публикует приложение только на `127.0.0.1:8080` хоста. Настройте существующий HTTPS proxy на этот адрес. Пример конфигурации установленного Caddy находится в [deploy/Caddyfile.example](deploy/Caddyfile.example): замените домен на свой и примените конфигурацию.

Остановка и повторный запуск в терминале с переданным `BOT_TOKEN`:

```bash
docker compose stop
docker compose start
```

## Пример запуска через Docker CLI

Для запуска без Compose в Bash сначала передайте `BOT_TOKEN`, как описано выше, затем выполните:

```bash
docker volume create quiz-duel-data
docker run -d --name quiz-duel --restart unless-stopped --stop-timeout 30 \
  -p 127.0.0.1:8080:8080 \
  --mount type=volume,source=quiz-duel-data,target=/data \
  -e BOT_TOKEN \
  quiz-duel:submission
docker logs -f --tail=100 quiz-duel
```

Публичный HTTPS proxy направьте на `127.0.0.1:8080`. Управление существующим контейнером не требует повторного ввода токена:

```bash
docker stop quiz-duel
docker start quiz-duel
```

Выберите один способ запуска. Не запускайте Docker CLI и Compose одновременно с одним токеном бота.

## Сервер с Caddy в Docker и автоматическим HTTPS

Если HTTPS proxy на сервере ещё не установлен, используйте конфигурацию из `deploy/`. Она запускает бота и Caddy в проекте `quiz-duel`; порт 8080 бота доступен только внутри Docker-сети, публично открыты TCP-порты 80 и 443.

1. Направьте A-запись домена на IP сервера. Если IPv6 не используется, удалите старую AAAA-запись для этого имени. Домен должен быть делегирован именно на DNS-серверы, где изменены записи.
2. Освободите порты 80 и 443 и разрешите входящие подключения к ним в сетевом экране.
3. В [deploy/Caddyfile](deploy/Caddyfile) замените `quiz-duel.ru` своим доменом, если используете другой адрес.
4. Из корня репозитория загрузите готовый образ или соберите `quiz-duel:submission`, как описано выше.
5. Передайте `BOT_TOKEN` и запустите:

```bash
docker pull caddy:2
cd deploy
sh ./start.sh
```

Если Docker требует права администратора:

```bash
sudo docker pull caddy:2
sudo --preserve-env=BOT_TOKEN sh ./start.sh
```

Caddy автоматически получает и продлевает сертификат. Пока DNS указывает на прежний сервер или делегирование ещё не обновилось, выпуск сертификата может завершаться ошибкой; Caddy повторяет попытки автоматически. Для полноценного входа в mini-app дождитесь доступности HTTPS без ошибки сертификата.

Для повторного запуска без передачи переменной можно хранить токен в файле `deploy/.secrets/bot-token`. Каталог должен иметь права `700`, файл - `600`; читать его должен только владелец или root. Этот каталог исключён из Git. `start.sh` читает файл, только если `BOT_TOKEN` не передан в окружении. При закрытом файле, доступном root, из каталога `deploy` запускайте `sudo sh ./start.sh`.

Команды управления существующими production-контейнерами не требуют повторного ввода токена:

```bash
sudo docker stop quiz-duel-bot-1 quiz-duel-caddy-1
sudo docker start quiz-duel-bot-1 quiz-duel-caddy-1
sudo docker ps --filter name=quiz-duel
sudo docker logs --tail=100 quiz-duel-bot-1
sudo docker logs --tail=100 quiz-duel-caddy-1
```

Контейнеры перезапускаются после перезапуска Docker. Журналы ограничены тремя файлами по 10 МБ для каждого контейнера. Для пересоздания используйте `start.sh` с переданным токеном или защищённым файлом; обычные команды Compose также требуют `BOT_TOKEN` при чтении конфигурации.

## Подключение к MAX

1. Дождитесь доступности публичного HTTPS-адреса без ошибки сертификата.
2. Укажите этот адрес в поле mini-app в кабинете бота MAX. Для сервера команды используется `https://quiz-duel.ru`.
3. Добавьте бота в группу и назначьте администратором. Это необходимо для работы со списком участников и администраторов.
4. В группе отправьте `/start`, затем `/app`, и откройте mini-app кнопкой бота.

Успешная авторизация в MAX отражается в журналах бота. Для дуэли второй участник принимает приглашение в группе; перед первым вопросом оба игрока нажимают «Готов», следующие раунды запускаются автоматически.

## Основные возможности

- `/start`, `/app` - меню и вход в mini-app из группы.
- `/duel` - открытый или адресный вызов, общий старт и таймер, 1-20 вопросов, результат и реванш.
- `/top`, `/stats`, `/members` - рейтинг, прогресс и участники текущей группы.
- `/teacher`, `/quiz` - кабинет учителя и экспресс-квиз.
- Предметы с обложками, банк вопросов с поиском и редактированием, аналитика и замечания по вопросам.
- По умолчанию в новой дуэли 3 вопроса, на каждый ответ - 15 секунд. Учитель может изменить количество. Новые предметы требуют по умолчанию 3 включённых вопроса; минимум настраивается от 1 до 20. Для старых предметов без этого поля сохраняется минимум 1.
- Вопросы учителя приносят двойные очки. XP начисляются за первые 3 дуэли с одним соперником в сутки в каждой группе.
- История, разбор ответов, восстановление активной игры, защита от повторного начисления XP и общая комната реванша.
- Все ответы и приглашения бота направляются в группу. Права учителя и членство проверяются на сервере; данные групп изолированы.

## Хранение, резервное копирование и обновление

База находится в `/data/quiz.db` контейнера. Используйте один процесс бота и постоянный локальный диск, не сетевую папку. Сохраняются пользователи, прогресс по чатам, предметы, вопросы, аналитика, история и незавершённые игры. Успешный ответ API отправляется после сохранения состояния; повреждённая база не заменяется пустой.

| Способ запуска | Хранилище |
| --- | --- |
| Корневой Compose | Именованный том `quiz-data` с префиксом имени Compose-проекта |
| Docker CLI из примера | `quiz-duel-data` |
| Production Compose | `quiz-duel_quiz-data`; сертификаты - `quiz-duel_caddy-data`, настройки Caddy - `quiz-duel_caddy-config` |

При повторных запусках используйте прежние имена проекта и томов. Остановка и обычный `docker compose down` сохраняют именованные тома. **`docker compose down -v` удаляет их.**

Перед обновлением штатно остановите бота и сохраните весь каталог `/data` или содержимое его тома. У работающей SQLite-базы актуальные записи могут быть в WAL: не копируйте только `quiz.db` во время работы. Для восстановления остановите приложение, верните каталог из копии, сохраните владельца и права (в контейнере UID 10001), затем запустите бот.

Для корневого Compose обновление из исходников: `git pull`, передача `BOT_TOKEN`, затем `docker compose up -d --build`. Для production-варианта соберите новый образ `quiz-duel:submission` из корня репозитория и из `deploy` выполните `sh ./start.sh` с правами Docker и доступным токеном. Перед пересозданием в новом терминале передайте токен снова либо используйте защищённый файл.

Старые общие очки из базы предыдущей версии при первом открытии распределяются по сохранённым играм групп. Прежние суммы сохраняются в архивном поле `LegacyProgress`; очки без истории не копируются в произвольную группу.

## Разработка

Сервер: **Go 1.27.3**, SDK MAX и SQLite. Интерфейс: HTML, CSS, JavaScript и Material Web с оформлением в стиле хакатона. Go-бинарник содержит UI, шрифты и иконки. Версии зависимостей закреплены в `go.mod`, `go.sum`, `package.json` и `package-lock.json`; полный список находится в `requirements.txt`.

Для пересборки Material-компонентов или набора иконок потребуется Node.js; при подготовке комплекта использовался Node.js 24.15.0:

```bash
npm ci
npm run build
```

Для обновления описания зависимостей:

```bash
node scripts/submission-dependencies.mjs
```

Для разработки без Docker передайте `BOT_TOKEN` и выполните `go run .`. HTTP-сервер по умолчанию слушает `127.0.0.1:8080`, база создаётся в `data/quiz.db` относительно рабочей папки. Для входа в mini-app всё равно нужен публичный HTTPS proxy и открытие через MAX.

## Готовый Docker-образ

Готовый Linux amd64 образ построен с Go 1.27.3 и Debian bookworm-slim. Версии системных пакетов, идентификаторы и контрольные суммы содержатся в [dist/IMAGE.json](dist/IMAGE.json) и [dist/SHA256SUMS](dist/SHA256SUMS).

## Сторонние компоненты и шрифты

- Лицензии Go-зависимостей: [licenses/GO-LICENSES.txt](licenses/GO-LICENSES.txt).
- Лицензии встроенных UI-компонентов: [web/vendor/LICENSES.txt](web/vendor/LICENSES.txt).
- Press Start 2P 3.000: `web/brand/press-start-2p.ttf`, лицензия [PRESS-START-OFL.txt](web/brand/PRESS-START-OFL.txt).
- Open Sans 3.003: `web/brand/open-sans.ttf`, лицензия [OPEN-SANS-OFL.txt](web/brand/OPEN-SANS-OFL.txt).

Оформление опирается на предоставленные гайд «Идея фикс» и презентацию команды «Алгоритм успеха». Шрифты взяты из каталога Google Fonts: `ofl/pressstart2p` и `ofl/opensans`. Они поставляются вместе с приложением, внешнего хостинга шрифтов не требуется. PDF, полная презентация и её иллюстрации в комплект не входят. SHA-256 шрифтов приведены в `dist/IMAGE.json`.

## Состав репозитория

```text
README.md                    все инструкции по сборке и запуску
Dockerfile, compose.yaml     сборка и запуск контейнера
requirements.txt             библиотеки и версии
main.go, internal/           бот, API, игровая логика и SQLite
web/                         UI, компоненты, шрифты и иконки
scripts/                     сборка UI и список зависимостей
dist/                        готовый образ, SHA-256 и метаданные
deploy/                      Caddy и production-конфигурация сервера
licenses/                    лицензии Go-зависимостей
```

В текущей конфигурации проверка подлинности TLS-сервера только для клиента MAX API отключена для совместимости с окружением команды. HTTPS mini-app настраивается отдельно в reverse proxy.

Рабочий токен, база пользователей, журналы чатов и регистрационные документы команды в репозиторий и Docker-образ не входят. Токен передаётся при создании контейнера и доступен администратору Docker; не публикуйте вывод `docker inspect`, `docker compose config` с настоящим токеном и не включайте трассировку shell при его чтении.
